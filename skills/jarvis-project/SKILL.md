# 五闸门项目协议

> 这个技能解决的是用户最在意的一件事：**不要单方面自主完成**。
> 用户要的是一问一答、他真的学到东西、他随时知道进展。

## 绝对禁止

- 拿到任务直接开工。
- 把第 3 道闸门的 `consent` 代填成 true。
- 把"我完成了"当汇报（没有证据的完成不算完成）。
- 跳过闸门。`jarvis_project(action="record")` 会拒绝跳跃，别绕。
- 用小项"顺手多做一点"来掩盖计划外的范围扩张。

## 五道闸门

### ① 题意还原（restate）
复述并请用户确认：
1. 任务是什么（一句话）
2. 边界：包含什么 / **明确不包含**什么
3. 交付物：最终要交出什么
4. 成功判据：怎样算做好了
5. 时间与资源：截止、可用时间、外部依赖

只要这五项里有任何一项写不出具体内容，就说明任务还没定义清楚 —— 停下来问，不要猜。

### ② 知识盘点（inventory）
产出两张清单 + 一个核对：
- **必须知识**：不做出来就做不成的
- **加分知识**：做得漂亮的
- **用户已经掌握的部分**：用 `jarvis_memory(action="recall")` 与 `jarvis_profile(action="read")` 先查档案，别问用户已经说过的事
- 明确标出档案里的已知缺口：点集拓扑 / 抽象代数与群论 / 实分析测度论 / 最优化理论

### ③ 差距补课（gap）
对每个缺口：
1. 用用户能接住的层次讲 —— 他爱数学、讨厌作业、习惯看 B 站网课。**给直觉 + 给可验证的例子**，不要只丢定义。
2. 讲完给**自测三问**，难度递增。
3. 用户答错就换一种讲法重讲，不要往下走。
4. 全部讲完，明确问：**"讲清楚了吗？可以开始了吗？"**
5. 只有得到肯定回答，才 `jarvis_project(action="record", gate=3, consent=true, ...)`。

补课产生的内容要用 `jarvis_knowledge(action="add", kind="theorem")` 沉淀，下次不用重讲。

### ④ 方案与创新度（plan）
- 1–3 条路线，每条写：做法 / 优点 / 代价 / 失败风险
- 问用户要**适当创新**还是**极致创新**，写进 `innovation`
- 给出 **WBS**：每项 30–60 分钟能做完，每项带验收判据，用 `jarvis_project(action="wbs")` 落盘
- **目标对齐器**（这是"大格局"的落地）：显式回答
  - 这件事对四条战线（A 课内 GPA / B 科研与论文 / C 数学丘赛 / D AI 全栈）的**边际贡献**是多少？
  - 有没有更高杠杆的替代做法？
  - 如果答案接近零，**直说"这事不值当"**，并给出替代方案。

### ⑤ 执行（execute）
每个小项固定四步：
1. **做**（保持小，别越做越大）
2. **自检**：逐条对照该项的验收判据，写 `selfCheck`
3. **第三方检查**：见 `jarvis-review` 技能，写 `thirdParty`
4. **汇报**：`jarvis_project(action="progress")` 带 `evidence` + `report`
   - 汇报格式固定：**做了什么 / 证据 / 剩余风险 / 下一步**
   - 证据必须是可验证的东西：文件路径、命令、输出、diff

执行中的三条纪律：
- **旁路问答**：用户随时插话提问，立刻回答，不改变当前 WBS 状态、不重置计划。
- **反脆弱压缩**：每完成一个小项就落 `STATE.md` + `DECISIONS.md`；上下文到 50%（常规）/ 30%（极复杂）之前先把"当前状态 + 待决问题"写盘，压缩后靠它无损接上。
- **不许沉默**：小项做完了必须汇报，做不下去也要汇报（说清楚卡在哪、需要什么）。

### 反退化护栏（卡住就停，不许硬磨）

> 2026-10-11 实测事故：在微分方程项目 1.3 的判据脚本 `check_mom.py` 上连续做了 **11 次「±1 行」编辑**（其中 2 次直接失败、`err:true`），思考内容退化成反复吐同一对短句（用户看到的就是一直刷「好。／（real。」），最后只能由用户**手动暂停**。这属于模型的重复退化（degeneration）——不是 DSH 的 bug，也不是压缩本身，但"长会话 + 卡在同一个改不动的地方"是它的放大器。

硬规则（触发即停，不许"再试一次"）：

1. **同一个文件，连续 ±1 行微调最多 2 次**。第 3 次之前必须先做一件**不同的事**：读回整个函数／整个文件、跑一次 `run_all.py` 看现状、或者换方法。
2. **同一个工具在同一个文件上连续失败 2 次 → 禁止第 3 次**。必须先读回文件确认当前内容——多数失败是"要替换的旧文本已经变了"。
3. **发现自己在重复**（同一句话／同一个片段／同一对词在思考里出现 ≥3 次）→ **立刻停手**，把当前状态写进 `STATE.md`，并对用户说一句："我卡住了，在重复退化，建议换方法／换会话。"
4. **同一小项连续 15 分钟没有实质进展**（没有新数字、没有通过的判据、没有落盘）→ 停下来报卡点，让用户决定。
5. **判据脚本不是"改到变绿"的东西**。验收判据定义"什么算做完"；判据本身写错了要**明写"判据设计错误"并记录理由**（照 D11 的做法），不许悄悄放水。

### 收官：大检查
全部小项完成后，做三件事：
1. **整合一致性**：各部分能不能拼成一个完整的东西？接口对得上吗？
2. **可复现性**：换个人（或换个时间）照文档能不能重做出来？
3. **对用户的价值**：跟第 4 道闸门承诺的边际贡献对得上吗？

然后**自检 + 第三方检查**，再呈现给用户，并回到第 4 道闸门等他提新需求。

## 工具对应表

| 动作 | 调用 |
| --- | --- |
| 立项 | `jarvis_project(action="open", name=..., goal=..., deliverable=..., deadline=...)` |
| 记录闸门 | `jarvis_project(action="record", gate=..., content=...)` |
| 拿到开工同意 | `jarvis_project(action="record", gate=3, consent=true, ...)` |
| 设定 WBS | `jarvis_project(action="wbs", items=[...])` |
| 推进 + 汇报 | `jarvis_project(action="progress", item=..., evidence=..., report=...)` |
| 看状态 | `jarvis_project(action="status", name=...)` |
| 沉淀知识 | `jarvis_knowledge(action="add", kind="theorem", ...)` |
