# 第三方检查官

> 为什么需要它：模型给自己打分天然会偏高（自我确认偏差）。
> 用户的要求是"每完成一小项都要自检 + **第三方检查**"，所以这里定义的是
> **一个立场，而不是一个工具**：换一个独立上下文、只带原始材料和验收判据、
> 带着"找出问题"的任务去复核。

## 怎么执行第三方检查

优先用 `subagent`（独立上下文，不带本轮的自我辩护）：

```
对下面这份产出做对抗性复核。你的任务不是确认它没问题，而是找出它有问题的地方。

【验收判据】<逐条抄过来>
【产出材料】<文件路径 / 命令输出 / diff；只给材料，不要给结论>
【作者自述】（可以给，但你必须独立验证，不许采信）

请输出：
1. 逐条判据的判定：通过 / 不通过 / 无法判定（无法判定要写清缺什么证据）
2. 发现的问题：每条给 位置（文件:行） / 问题 / 最小可复现方式 / 严重度
3. 最小反例：能推翻作者结论的最简例子（找不到就写"未找到反例，且已尝试 X/Y"）
4. 你没检查到的部分：明确列出覆盖边界
```

如果 `subagent` 不可用（或任务很小），退而用「换尺子」自检，但必须**换判据来源**：

- 用**用户给的原始要求**逐字对照（不是用自己总结过的版本）
- 用**可执行的东西**验证：能跑就跑，能算就算，能查就查；不许只靠"读了一遍觉得对"
- 主动找反例，并把找反例的过程写出来

## 判定纪律

- **默认不通过。** 需要正面证据才能判通过。
- `通过` 必须附带：判据逐条对应 + 你实际做的验证动作。
- 发现的问题分级：
  - `blocker` —— 结论就是错的 / 交付物不可用
  - `high` —— 关键判据没满足
  - `medium` —— 会误导用户
  - `low` —— 表述、格式、可读性
- **不许**写"整体上没问题"这种没有判据映射的话。
- **不许**为了显得尽责而编造问题；找不到问题也是合法结论，但要写清你覆盖了什么、没覆盖什么。

## 输出模板

```
## 第三方检查结论：<pass | needs_revision | reject>

### 判据核对
| # | 判据 | 判定 | 证据 |
| --- | --- | --- | --- |
| 1 | ... | 通过/不通过/无法判定 | ... |

### 发现的问题
- [严重度] 位置：问题；最小可复现：...；建议修法：...

### 最小反例
- ...

### 覆盖边界（我没检查的）
- ...

### 下一步
- 修什么、谁来修、修完怎么验
```

## 与五闸门的关系

- 小项级检查：结果写进 `jarvis_project(action="progress", thirdParty="...")`
- 收官级检查：作为"大检查"的第二票，与自检并列呈现给用户
- 任何 `blocker` 出现时：**停止推进**，先修，再重新检查，不许带着 blocker 往下做
